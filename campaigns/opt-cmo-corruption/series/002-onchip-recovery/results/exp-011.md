# Result: exp-011, noise-referenced thresholded writes

## Validated short screens

Each screen uses 2,097,152 synthetic input tokens, 256 optimizer updates and
constant LR 3e-3. The threshold is a multiple of the **nominal mid-range**
write-noise standard deviation, 0.01413954 normalized q units. Actual device
noise remains conductance-dependent. Every row starts from exactly the same P0;
the held development KL is 0.13669190.

## Interpretation and decision

The short and full results support accumulated writes on this array: useful adaptation is
possible under the same idealized noisy-write law once many small commands are
combined into fewer larger writes. This comparison changes update timing,
magnitude and noise exposure together; it does not isolate their separate
causal contributions. It also does not validate the endpoint-derived incremental
noise law or its unclamped extrapolation.

The dense 50M-token exp-008 reference used 167.49 billion healthy writes and
ended at development KL 0.402117. The thresholded run uses 148.09 times fewer
writes and improves performance, but that full dense reference used LR 5e-3,
so this is not an isolated matched-LR full-pass comparison. The short dense
3e-3 screen provides the matched-LR contrast. Among completed 50M-token digital
LoRA comparisons, thresholded adaptation performs better than ranks 4 and 16
but worse than rank 64 on all three KL cohorts. Rank 64 reaches development KL
0.051739 and WikiText KL 0.095709 with no physical writes, at the cost of
2,949,120 digital adapter parameters and extra MACs per token; it also uses a
different selected LR. This does not establish physical-learning superiority.

**Scoped verdict:** accumulated thresholding changes the negative dense result
into useful recovery for this one array and defect case. Longer constant-LR
training adds substantial writes without a clear endpoint benefit over the short
screen. Out-of-range states grow, and the underlying endpoint-derived incremental
write-noise model remains an exploratory assumption. Performance does not establish
physical viability beyond the best matched no-weight-learning alternatives.

**Next decision:** stop the declared pilot at its frozen final endpoint. A future
development comparison should test a shorter fixed duration and LR decay before
adding epochs, then check independent arrays and the missing matched no-weight-
learning controls. These are recommendations, not newly dispatched runs. Simply
discarding small commands is insufficient at this LR; signed accumulation is
essential to the improvement observed here.
